## Decomposition

Feature: add a "tags" feature to the sandbox notes app. Notes get zero or more free-text tags; the home view shows chips and a filter bar.

1. **Extend note dict shape** — add `"tags": []` to every note appended in `app.py`'s `new_note` POST handler. Verify: existing tests still pass; a note created with no tags field has `note["tags"] == []`.

2. **Parse tags from form input** — in the `new_note` POST handler, read the `tags` form field, split on commas, strip whitespace, drop empty strings. Verify: input `"work, urgent, "` → `["work", "urgent"]`; blank input → `[]`.

3. **Add tags input to `new_note.html`** — a text input named `tags` with a label hinting comma-separated values; pre-populate with `{{ tags_value or '' }}` on re-render. Verify: submitting `"work, urgent"` stores `note["tags"] == ["work", "urgent"]`.

4. **Display tag chips in `home.html`** — for each note, render `note["tags"]` as small chip `<span>` elements beside the title. Verify: a note with `tags=["work"]` produces HTML containing the text "work" inside a chip element.

5. **Collect unique tags in the `home` view** — compute the sorted list of all unique tags across `app.notes` and pass as `all_tags` to the template. Verify: with notes tagged "personal" and "work", `all_tags == ["personal", "work"]`.

6. **Add filter bar to `home.html`** — render an "All" link followed by one link per tag in `all_tags`; active tag is visually highlighted. Verify: rendered page contains link text for each unique tag present in notes.

7. **Add `?tag=` filter logic to the `home` view** — if `request.args.get("tag")` is set, pass only notes where that tag is in `note["tags"]`; no param shows all notes. Verify: `GET /?tag=work` response contains only work-tagged note titles, not notes tagged only "personal".

8. **Write tests for tag parsing** — `tests/test_tags.py`: empty string → `[]`, single tag, multi-tag with extra whitespace, trailing comma. Verify: all new tests pass.

9. **Write tests for filter behavior** — same file: `GET /` returns all notes; `GET /?tag=work` returns subset; `GET /?tag=nonexistent` returns empty list. Verify: all filter tests pass.

10. **Full regression check** — run `pytest` with no filters. Verify: all existing tests (including `test_task_01.py`) still pass alongside the new tag tests.

## Task 1 context brief

Goal: add a `tags` key to every note dict and parse the tags field from the new-note form. A note is currently `{"title": "...", "body": "..."}` — after this task it should be `{"title": "...", "body": "...", "tags": [...]}`.

Constraints:
- Tags are a list of strings on the note dict — no new model, no database, no separate table.
- Parse from a single comma-separated form field: split on `,`, strip whitespace from each part, drop empty strings.
- Default to `[]` when the field is absent or blank.
- Do not touch `home.html` or the filter logic — that is a later task.
- Existing tests must still pass without modification.

Files to change:
- `app.py` — `new_note` POST handler only

Acceptance:
- A note submitted with no tags field has `note["tags"] == []`.
- A note submitted with `"work, urgent"` has `note["tags"] == ["work", "urgent"]`.
- A note submitted with `"  work , , urgent "` has `note["tags"] == ["work", "urgent"]` (whitespace and empty parts stripped).
- `pytest tests/test_task_01.py` still passes.
