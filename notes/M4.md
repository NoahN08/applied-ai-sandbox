## Bug hunt #4 — hardcoded secret

**Bug:** The OpenAI API key is hardcoded as a string literal in source code. The moment this is committed, the key is in git history permanently — even if you delete it in a later commit. Bots scan GitHub for `sk-proj-` patterns within seconds of a push and will drain the quota or rack up charges before you notice.

**Why Claude wrote it this way:** Claude optimizes for "show a working example immediately." Hardcoding the key makes the snippet runnable without any setup instructions. It treats the key like a placeholder even when the value looks real — it was focused on demonstrating the API call pattern, not on the security boundary between code and credentials.

**Fix (env var + key rotation):**

```python
import os
import openai

client = openai.OpenAI(api_key=os.environ["OPENAI_API_KEY"])
```

Set the key in your shell (`$env:OPENAI_API_KEY = "sk-..."`) or a `.env` file that is listed in `.gitignore`. And treat the exposed key as already compromised — rotate it in the OpenAI dashboard immediately regardless of whether it was pushed.

## Bug hunt #3 — edge case

**Bug:** `average_rating([])` raises `ZeroDivisionError: division by zero` — `len([])` is 0, so `sum([]) / len([])` divides by zero. Confirmed by running it directly.

**Why Claude wrote it this way:** Claude wrote the test for the happy path it was thinking about (`[4, 5, 3]`) and never considered the empty-list input. Tests written by the same model that wrote the code share the same blind spots — Claude didn't think of the edge case when coding, so it didn't think of it when testing either.

**Fix:** Guard against an empty list before dividing:

```python
def average_rating(ratings):
    """Return the average of a list of ratings."""
    if not ratings:
        return 0.0
    return sum(ratings) / len(ratings)
```

The deeper lesson: always ask "what happens with empty input, zero, or None?" — Claude will miss these unless you prompt for them explicitly.

## Bug hunt #1 — SQL injection

**Bug:** The user-supplied query parameter `q` is interpolated directly into the SQL string with an f-string. An attacker can pass `q = "' OR '1'='1' --"` to make the `WHERE` clause always true and return every row — or craft a payload that drops tables or exfiltrates data from other tables.

**Why Claude wrote it this way:** Claude learned from code samples where f-strings are used for all string formatting. Raw SQL with an f-string looks syntactically tidy and matches common tutorial snippets that never route user input into the query. Without an ORM making parameterization the obvious default, Claude pattern-matched on form rather than on safety.

**Fix:** Use bound parameters so the database driver handles escaping — never the developer:

```python
from sqlalchemy import text

rows = db.session.execute(
    text("SELECT id, title FROM notes WHERE title LIKE :pattern"),
    {"pattern": f"%{q}%"}
).fetchall()
```

The `%{q}%` stays in Python for the LIKE wildcards; the actual user value travels through the parameter slot `:pattern` where the driver sanitizes it automatically.

## Bug hunt #2 — hallucinated package

**Bug:** `flask_simpleauth` does not exist — `pip show flask_simpleauth` returns "Package(s) not found". The code imports cleanly at write-time because Claude invented the package name, but it crashes at runtime with an `ImportError` the moment you try to use it.

**Why Claude wrote it this way:** Claude blended the real package (`Flask-Login`) with plausible-sounding naming conventions (`flask_simpleauth` follows the `flask_<thing>` pattern of real packages like `flask_sqlalchemy`). It generated a name that *looks* correct without verifying it exists on PyPI — a classic hallucination where surface plausibility substitutes for factual accuracy.

**Fix:** Replace with the real package. `Flask-Login` provides exactly these symbols:

```python
from flask_login import LoginManager, login_required

login_manager = LoginManager()
login_manager.init_app(app)
```

Always run `pip show <package>` or check PyPI before trusting a package name Claude produces.
